# 普通微信抽取工具现状快照

快照日期：2026-05-28。微信客户端和开源项目变化很快，实际开工前必须重新核对。

## 结论

普通微信数据库抽取的开源生态已经明显收缩。几个核心项目在 2025-10 之后出现删库、停更、归档或只剩说明文件的状态。后续不能默认“GitHub 上有现成完整代码可直接拉下来跑”，更稳妥的做法是：

1. 先用官方迁移或 PC 已登录账号把自有聊天记录同步到本机。
2. 用只读脚本定位文件和版本。
3. 把第三方工具作为可替换 adapter，运行前重新做来源、版本、合规、离线隔离检查。
4. 我们自己的代码只接收“已授权、已解密、或本地 HTTP API 已提供”的数据，再做 schema 检查和归一化。

## 重新开工时的审计清单

- 仓库是否还存在、默认分支是否含源码、release 是否可下载。
- 最近 commit、issue、release 日期，是否有删库/律师函/合规声明。
- 支持的微信版本，特别是 Windows 4.x 的数据库结构和 key 获取限制。
- 是否要求管理员权限、关闭安全功能、读取进程内存或注入进程。
- 是否能离线运行，是否上传数据、日志、key、联系人或消息。
- 输出格式是否稳定：SQLite、JSON、CSV、HTTP API、PostgreSQL、MCP。
- 能否只跑“已有 key/已有解密 DB”的离线模式，避免在不必要时碰 live process。

## 本 kit 的边界

本 kit 保留定位、schema、归一化和 adapter 规范，不保存第三方破解实现。这样后续即使某个项目失效，也只需要替换 adapter，不影响数据库检查、解密结果处理和文本导出。
